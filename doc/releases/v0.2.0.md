# Orbyte v0.2.0

Author: jaswtao · Date: 2026-10-26

This release includes all nine source commits after v0.1.0, plus the v0.2.0 release metadata.

## New features and improvements

- **Editor draft recovery:** persist local recovery drafts, discover them at startup, and restore, copy or discard them from the workspace menu. Recovery refreshes when reopened, can be skipped, and remains available when workspace loading fails. Revision checks and rename migration protect newer drafts; restoring a draft updates the editor buffer without automatically overwriting the source file.
- **Faster filename search after edits:** reuse the filename index for content edits, Git internal changes and atomic saves. Structural changes and ignore-rule changes still invalidate the index. Repeatable 10k/90k file benchmarks and validation records are included.
- **Application diagnostics:** add structured JSON Lines logs for application lifecycle, database and terminal events, frontend errors and command outcomes, with correlated metadata, daily/2 MiB rotation, 30-day retention and legacy log cleanup.
- **Getting started:** add Chinese and English quick-start guides and improve README introductions and download links.

## Fixes

- Decode terminal frames correctly when IPC falls back to JSON byte arrays, including reconnects and background output recovery.
- Position terminal IME candidates correctly for RGB visual cursors, palette colors, wide characters and long compositions.
- Deliver text clipboard paste through native Ctrl+V in Windows Codex sessions, with shared-console detection to exclude separate or detached consoles.
- Keep terminal unread indicators accurate across redraws and reconnects by comparing against the last-read content snapshot.
- Prevent Alt, F10 and Alt+Space from unexpectedly activating the Windows system menu.

## Dependencies and release checks

- Update Tokio to 1.53.3 and clipboard-win to 5.4.3, refresh third-party notices, and handle advisory-free yanked warnings in dependency auditing.
- Expand regression coverage for draft recovery, index invalidation, diagnostics, native input and terminal activity.
- The tagged release workflow runs Windows tests, frontend type checking/build, dependency audits, secret/history scans, license verification and Rust 1.90 compatibility checks before packaging.
- Manual installation and desktop acceptance are incomplete. Automated checks do not certify the unexecuted scenarios in the [release checklist](https://github.com/jaswtao/Orbyte/blob/v0.2.0/doc/release-checklist.md) and [acceptance record](https://github.com/jaswtao/Orbyte/blob/v0.2.0/doc/next-stage-validation.md).

## Installation and verification

Download `Orbyte_0.2.0_x64-setup.exe` and compare its SHA-256 hash with `SHA256SUMS.txt` before installing:

```powershell
Get-FileHash .\Orbyte_0.2.0_x64-setup.exe -Algorithm SHA256
```

The Windows x64 installer is unsigned. Microsoft Edge WebView2 Runtime is required and its setup may download Microsoft components. Git, WSL, Codex and Claude Code are optional external tools and are not bundled. Back up application data before upgrading; native upgrade acceptance has not been completed.

## Known limitations and local data

- Restart restores projects, layouts and file paths. Draft recovery offers the last successfully persisted editor draft; it does not restore running processes or terminal output and cannot guarantee recovery of edits made before the latest draft write.
- UNC/WSL network project directories are unsupported. The text editor and recovery drafts have a 5 MiB limit.
- Windows managed child processes stop with their terminal. Detached WSL processes and Linux services may outlive a terminal session.
- Clipboard screenshots remain in the application cache until manually removed.
- Application data is stored under `%APPDATA%\com.orbyte.desktop\`; clipboard images are under `%LOCALAPPDATA%\com.orbyte.desktop\clipboard-images\`. Back up these directories before deleting data. Uninstall cleanup behavior has not been verified; do not assume uninstall removes user data.
