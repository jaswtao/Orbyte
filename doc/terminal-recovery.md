# 终端输出停滞修复与验证

Author: jaswtao  
日期：2026-10-20

## 问题与修复

现场表现为 Codex 仍收到按键，而 Orbyte 显示停在旧内容；结束进程后界面仍显示运行中。最初触发点没有持久日志，不能认定为单一网络错误。

本次修复隔离终端帧和回调异常，防止异常中断 Tauri Channel 的有序消息处理；输出确认失败保留进度并串行重试。会话状态每两秒通过独立查询同步，终端结束、关闭及重新启动不再依赖输出通道通知。

可见终端发现帧异常、订阅失效，或有未确认输出且持续停滞十秒时，每个运行时会话最多自动重连一次。再次异常显示“重连输出”按钮。重连保留进程和已显示内容，清除未发送输入，不重放已发送按键；通过重新订阅、尺寸变化触发重画，并等待实际解析到输出后才恢复输入。期间不自动重启 Codex，也不提交命令或模型请求。

重连可能缺失部分未显示输出，不能保证完整历史回放。空闲终端不因没有输出被误判，隐藏终端恢复可见后重新观察。

### 2026-10-22：修复重连后再次禁用输入

安装版日志出现 `ReconnectSucceeded` 后立即连续 `FrameError`，最终确认停滞。Tauri 2.12.2 在自定义协议通信失败后回退到 postMessage，大块原始响应可能被序列化为 JSON 字节数组；小帧仍直接返回 `ArrayBuffer`。原解码器只接受 `ArrayBuffer`，会将回退路径的正常输出误判为坏帧并暂停输入。重连的小帧通过后，大块重绘再次触发同样问题。

解码器现在兼容两种传输形式，并逐字节校验数组，拒绝越界、非整数或非数字值。新增回归测试覆盖真实 Tauri Channel 接收字节数组、输出确认、重连期间混合两种帧、旧订阅隔离，以及恢复后继续发送输入。

用户补充的触发步骤为：点击 Codex 提供的链接，在自动打开的浏览器完成操作后返回 Orbyte，输入不可用并出现警告。新增模拟测试覆盖后台延迟确认、后台字节数组输出、返回可见后混合帧重绘及继续输入；桌面端全部 147 项测试通过。该测试没有实际打开浏览器，也未执行登录或授权。尚未在安装版实机确认浏览器跳转是否直接触发通信回退；现有 `FrameError` 日志未包含具体异常来源，不能仅凭日志排除其他前端异常。

## 诊断日志

日志位于 Tauri 应用数据目录的 `logs/orbyte-<UTC日编号>-<分片>.log`（日编号为 Unix 时间戳秒数整除 86400）。Windows 默认目录为 `%APPDATA%\com.orbyte.desktop\logs`，开发版为 `%APPDATA%\com.orbyte.desktop.dev\logs`。JSON Lines 的 `timestamp_ms` 为 Unix 毫秒时间，`pid` 区分进程，`target` 区分来源。单个文件达到 2 MiB 或 UTC 日期变化时切换文件；重启续写当天分片，不覆盖已有日志。按日桶最多保留最近 30 天，桶内最早记录到期时整桶删除，因此边界日可能提前删除部分记录。启动、跨日写入及每小时执行清理，未运行时在下次启动清理；删除失败时报告错误并重试。旧版 `terminal.log`、`terminal.log.1`、`terminal.log.2` 按最后修改时间参与清理。

应用日志还记录数据库错误、启动/退出、退出超时、Rust panic 的位置和堆栈、前端异常的代码位置。操作开始/结束日志使用同一 `request`，附带项目/会话 ID、结果和耗时；高频终端输入、ACK、尺寸变更和状态轮询仅记录错误或超过 1 秒的调用。前端不上传参数、返回值、任意错误正文或 rejection 值；文件错误仅记录类别。排查时先按 `ERROR`/`WARN` 定位，再按请求或会话 ID 关联前后记录。

记录时间（Unix 毫秒）、会话 ID、订阅代次、帧序号、缓冲和在途字节数、确认空闲时长，以及读取失败、发送失败、恢复和退出事件。不记录终端正文、键盘输入、剪贴板或认证令牌。前端上报仅允许固定事件枚举，且受 Tauri 命令权限约束。

## 验证

- 自动测试覆盖：真实 Tauri Channel 的坏帧隔离、确认失败重试及旧订阅隔离、隐藏及空闲判定、单次自动恢复额度、退出后的尾部输出、暂停期间丢弃输入、停止失败后的状态恢复。
- Windows ConPTY 测试覆盖：输出窗口占满且不确认时，退出状态仍可查询，注册项仍可移除。
- 日志测试覆盖：大小/跨日轮转、重启续写、30 天边界、旧日志清理、时钟回退、结构化输出与日志过滤。
- 隔离桌面测试：注入坏帧后自动恢复；再次丢弃输出通道，手动重连后中文输入正常；结束后出现“重新启动”，关闭后会话列表为空。
- Codex 实测：隔离实例中注入坏帧，恢复前后 PID 保持为同一个进程，中文草稿重新可见；未提交模型请求。

验证命令：

```powershell
pnpm --filter orbyte-desktop test
cargo test -p orbyte-terminal
cargo test -p orbyte-desktop --test terminal_commands --test app_logging
pnpm build
```

终端测试中的外部 difftool 窗口激活测试需要专门的交互桌面和工具路径，默认跳过；其他测试须通过。

## 安装

安装包输出：`target/release/bundle/nsis/Orbyte_0.1.0_x64-setup.exe`。

先保存编辑器文件并处理其他终端的运行任务，再退出旧版进行安装。此次不自动关闭或覆盖正在使用的应用，不迁移或清除 Codex 对话、登录状态与项目数据库。
