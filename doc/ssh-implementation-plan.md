## 实现方案

### 背景与目标

已核实的项目现状：

- 桌面端使用 Tauri 2、Vue 3、TypeScript、xterm.js，后端为 Rust，SQLite 存储通过 SQLx 管理。
- `crates/orbyte-terminal/src/backend.rs` 通过 `portable-pty` 启动本地程序，要求工作目录在本地存在；Windows 会话使用 Job Object 管理进程。
- `TerminalManager` 和 `TerminalSession` 负责本地终端的输入、尺寸、状态、退出与输出订阅。`output.rs` 提供输出流控，前端 `TerminalClient` 使用二进制 Channel、序号与 ACK 接收输出。
- `TerminalConfig`、前端 `ShellType`、`validate_shell` 和数据库 `t_terminal_config.shell_type` 只支持 PowerShell、CMD、WSL。终端配置通过工作区关联本地项目。
- 现有布局仅支持 terminal、editor、split。`WorkspaceView.vue` 在工作区激活时，会把尚无会话且状态为 starting 的已保存本地终端自动启动。远程连接不能复用这套自动启动。
- `orbyte-files` 和现有文件命令面向本地项目，路径校验包含 Windows 保留名称及大小写规则，不能直接用于 Linux 远程路径。
- 应用已有统一退出确认、诊断封装、中英文界面、命令权限白名单和发布检查流程；尚无独立 SSH／SFTP 模块。

目标是在 Orbyte 内完成“保存服务器 → 验证主机 → 登录 → 交互终端 → 浏览服务器目录 → 上传／下载”的闭环（C01），保留现有本地项目行为。

### 方案概述

新增独立的“远程连接”入口和工作区，不要求用户先添加本地目录。连接配置与本地项目分别存储；远程终端复用 xterm 显示、输入队列和输出帧协议，网络连接与 SFTP 由 Rust 持有。

本方案的工程设计决定如下。这些是具体实施选择，区别于上表中的用户范围确认：

| 事项 | 设计决定 |
| --- | --- |
| 协议实现 | 使用内嵌 `ssh2`／libssh2，SSH2 交互会话加 SFTP；不调用 PuTTY 或解析外部 ssh／sftp 的交互文本。 |
| 凭据保存 | 保存主机、端口、用户名、认证方式及私钥路径；首期不持久化密码和私钥口令，也不复制私钥。同一次登录输入只在内存中用于该工作区本次待连接的终端和 SFTP，全部尝试结束后立即清除。 |
| 主机密钥 | 按规范化端点加算法保存公钥。已保存算法优先协商。公钥字节不匹配时拒绝认证，不能静默换钥，也不能降级到未信任密钥。 |
| 算法 | 显式限制主机密钥和公钥签名为 Ed25519 与 RSA-SHA-2，并排除 SHA-1 密钥交换和 MAC。协商出现这些弱算法即断开。 |
| 保活 | 每 30 秒发送要求回复的探测；满 30 秒无应答计一次，连续 3 次标为失效。探测发送成功不等于对端仍存活。 |
| 会话隔离 | 每个终端使用独立 SSH 连接；每个远程工作区使用独立 SFTP 连接，目录浏览和传输串行调度。远程会话不参加本地终端失联轮询，远程输出不解析本地 Shell 集成序列。 |
| 重连 | 网络断线后由用户手动重连；不自动重放命令、不自动续传。 |
| 布局恢复 | 重启恢复远程 Tab 和窗格，但保持离线，用户点击连接后认证。 |
| 文件传输 | 支持文件／目录、多选、进度、取消、失败后重新传输；不实现断点续传。远程提交无法安全替换时失败并保留原文件；本地下载用目标目录内的替换式重命名完成覆盖。 |
| 文件管理 | 支持刷新、进入／返回目录、创建目录；首期不提供远程删除、权限编辑、同步与远程文本编辑。残留临时文件只报告路径，由用户在终端中删除。 |
| 退出 | 只有未保存本地编辑和排队／运行传输拦截应用退出。仅有远程终端时直接退出。关闭单个远程终端始终提示远端任务可能仍在运行。 |
| 协议测试 | 真实服务器探针默认不随 `cargo test` 运行，由发布检查显式启动隔离 OpenSSH。 |

`ssh2` 提供会话、密码及私钥认证能力；Channel 提供 PTY、Shell 和尺寸变更能力，SFTP 提供目录和文件接口。选型依据见 [ssh2 官方文档](https://docs.rs/ssh2/latest/ssh2/)、[Session 文档](https://docs.rs/ssh2/latest/ssh2/struct.Session.html)、[Channel 文档](https://docs.rs/ssh2/latest/ssh2/struct.Channel.html)。实际依赖版本在步骤 1 的 Windows 编译和协议验证通过后锁定到 `Cargo.lock`，不得仅根据 API 存在判断安装版可用。

### 详细设计

#### 1. 页面与交互

- 侧栏增加“本地项目／远程连接”切换，远程列表显示连接名称、`用户@主机:端口` 和连接状态，支持新建、编辑、删除连接及打开工作区。
- 连接表单提供名称、主机、端口（初始值 22）、用户名和密码／私钥认证方式；密码与私钥口令在登录时输入，私钥通过原生文件选择器选择。一次「连接」只弹出一个密码或口令框，供该工作区当前所有待连接终端和 SFTP 使用。稍后单独新开的终端或重新建立的 SFTP 再次索取。
- 远程工作区采用终端与远程文件面板并排布局；终端支持多个 Tab 和分屏。远程视图不挂载本地编辑器、Git、worktree、文件索引和草稿恢复入口。
- 关闭远程终端或远程窗格时始终提示远端任务可能仍在运行，不受「关闭页签和窗格前确认」开关影响。该开关的本地判断依赖本机子进程，远程会话不使用它来跳过提示。
- 文件面板显示当前绝对路径、名称、类型、大小和修改时间；提供刷新、上传、下载、创建目录。目录进入通过 SFTP 查询，不向终端拼接 Shell 命令。面板不提供远程删除；传输残留的 `.orbyte-transfer-<UUID>.part` 只显示精确路径，由用户在终端中删除。
- 上传由本地文件／目录选择器发起；下载选择本地目标目录，不要求落在某个本地项目中。首期以按钮为必需入口，不要求实现系统拖放。目录对话框由 Rust 命令打开。
- 传输列表显示方向、相对路径、已传字节、总字节、速度、状态和错误原因；扫描目录期间显示“扫描中”，不使用尚未确定的总量计算百分比。
- SSH 终端只支持文本粘贴。远程会话不走 `registry.ts` 里把剪贴板图片存成本机路径再写入终端的分支，也不套用 Windows／WSL 路径粘贴。上传图片通过文件传输入口进行。

#### 2. 持久化与数据模型

通过新的追加迁移创建下列表，不修改历史迁移，也不修改本地项目路径约束。迁移编号以实施时仓库最大编号加一为准。

| 新增表 | 主要字段与约束 |
| --- | --- |
| `t_ssh_connection` | `id`、`name`、`host`、`port`、`username`、`auth_type`、`private_key_path`、排序及时间字段；端口 1–65535，认证方式 password／privateKey，私钥方式要求路径。允许同一主机配置多个用户／名称。 |
| `t_ssh_known_host` | 规范化主机、端口、主机密钥算法、公钥字节及 SHA-256 指纹。唯一约束是规范化主机、端口与算法，同一端点可以有多条算法记录。比对同时核对算法和公钥字节。 |
| `t_remote_workspace` | `id`、`connection_id UNIQUE`、布局版本、布局 JSON、上次浏览的远程目录；外键关联连接，级联删除。 |
| `t_remote_terminal_config` | `id`、`remote_workspace_id`、名称、排序和时间字段；外键关联远程工作区，级联删除。 |

运行态模型分开表示 `connectionId`、`remoteWorkspaceId`、`terminalConfigId`、`terminalId`、`transferId`，禁止将持久化配置 ID 当作网络会话 ID。连接编辑只影响后续连接，运行中会话保留连接参数快照。删除连接需先确认并结束所属终端及传输，再删除配置；取消删除不影响运行态。

远程布局使用单独存储的版本化布局，首版只接收 terminal／split，并验证所有终端配置属于同一远程工作区。抽取现有布局中的纯树操作供两个视图复用，但保留本地布局序列化格式和恢复规则。损坏的远程布局仅修复其自身，不删除连接配置。

传输记录首期仅保存在 Rust 内存中；重启不恢复排队任务。文件冲突决定期间不持有数据库事务或会话全局锁。配置查询、排序和删除按集合操作，不在目录遍历中执行数据库 CRUD。

#### 3. SSH 握手、主机验证与认证

连接状态：`idle → connecting → verifyingHost → authenticating → ready → closing → closed`；任一步错误进入 `failed`。用户取消、连接超时和应用退出都可终止当前尝试。

1. 后端校验主机与端口，不接受 `user@host`、URL 或命令行选项作为主机值；支持 DNS、IPv4、IPv6。DNS 名比较前转为小写。用户输入的 IPv6 去掉方括号后收成同一种压缩写法，因此 `::1` 与全写形式命中同一信任记录。端口缺省按 22 存储。规范化不通过解析后的 IP 替换用户配置的 DNS 信任身份。
2. 解析和 TCP／握手各设 10 秒上限。每条 SSH 连接的会话循环运行在专用操作系统线程上，不使用 Tokio 通用执行器，也不长期占用 `spawn_blocking` 线程池；退出清理本身使用该池。取消、失败和应用退出都通过关闭 socket 立即中止尝试，不等待 10 秒握手超时结束。取消后迟到的解析结果不得创建会话。
3. 握手前设置算法偏好：主机密钥和公钥签名只允许 `ssh-ed25519`、`rsa-sha2-512`、`rsa-sha2-256`，并排除 SHA-1 密钥交换和 MAC。协商出现允许列表之外的主机密钥，或出现 SHA-1 密钥交换、MAC 时断开，且此时尚未发送密码。已保存的算法排在协商列表前面。
4. 握手后先获取主机密钥，再认证。第一次见到某个端点的某个算法时，显示主机、端口、算法和 SHA-256 指纹，可选择“仅本次信任”“信任并保存”“取消”。该算法尚无记录时，不覆盖同一端点上其他算法的记录。
5. 本次算法已有记录而公钥字节不一致时拒绝认证，并显示原、新指纹。不能静默换钥，也不能从已信任算法落到另一把未信任密钥上完成登录。用户需在连接管理中按算法移除旧记录后重新连接。
6. 信任挑战包含一次性 challengeId，绑定本次尝试、端点、算法及密钥；连接已取消、超时或 generation 改变后，迟到的确认失效。等待用户输入最长 120 秒，期间不占用数据库锁。
7. 用户输入的密码／口令通过专用命令交给后端。前端提交后清空输入。同一次输入只保存在这次连接动作中，供当前待连接的终端和 SFTP 依次认证；全部尝试成功、失败或取消后立即从内存清除。稍后新开终端或重新建立 SFTP 时重新输入。私钥路径可以保存，私钥内容不得进入前端、数据库或日志。认证失败信息不得回显密码、口令或私钥内容。
8. 私钥验收覆盖 OpenSSH Ed25519 和 RSA（含加密私钥），RSA 使用 SHA-2 签名。PuTTY `.ppk`、SSH agent、keyboard-interactive／MFA、证书认证及系统 ssh_config 导入不属于首期。服务器只提供 keyboard-interactive 而没有 `password` 方法时，认证失败并说明该方法不在首期范围，不把口令送入交互问答。

SFTP 新建连接执行同一套主机校验和算法限制。一次连接动作中的密码供终端和 SFTP 共用，认证阶段结束后释放，不能借“保存连接”留在内存或数据库中。

#### 4. 终端运行时与输出复用

新增 `crates/orbyte-ssh` 管理网络、认证、SFTP 与取消；不把 SSH 实现放进 `orbyte-platform` 的本地 Shell 探测模块。

在 `orbyte-terminal` 中抽取最小的会话运行接口：写入、resize、停止、状态、订阅和 ACK。现有本地 PTY 实现继续由原管理器持有；SSH 会话适配相同的输出协议，由桌面层按 session kind 路由。保留 `TerminalManager` 对本地进程激活和 Job 的专用处理，SSH 返回“不支持原生粘贴／进程激活”。

SSH 会话请求 `xterm-256color` PTY、设置初始行列数后启动交互 Shell；resize 转成远程窗口尺寸变更。Ctrl+C 等按键作为终端输入发送。网络断开时保留屏幕内容，禁用输入并展示重新连接入口；新会话使用新 terminalId 和 generation，丢弃旧输入队列。

每条 SSH 连接由单个专用操作系统线程独占 `ssh2::Session`，使用非阻塞 I/O 和 socket readiness 驱动，处理部分读写及 EAGAIN。输入队列有界，轮流处理输出、输入、resize、保活和取消，不在无限阻塞的 read 上等待。不得通过克隆 Session／Channel 加多个阻塞线程获得所谓并发；库的阻塞模式会影响关联通道，参见 [Session 文档](https://docs.rs/ssh2/latest/ssh2/struct.Session.html)。

复用 `FlowState` 的帧序号、ACK 和内存上限，并复用其输出缺口提示；消费暂停或输出过多不得无限增长内存。前端输出重订阅只是 WebView 订阅恢复，与 SSH 网络重连分开表示，后者不能伪装为现有终端仍在运行。

远程会话使用独立注册表。`TerminalRegistry.syncSessions()` 只根据 `list_terminal_sessions` 判断本地 PTY：名单里没有某个远程 `terminalId` 时，不得把该终端标成已退出。远程 `TerminalClient` 关闭本地 Shell 集成解析，忽略 OSC 133 等序列，从而不触发本地 Git 刷新或命令完成通知。`terminal_uses_native_paste` 和本机进程激活对远程会话返回不支持。

保活间隔 30 秒。每次发送要求对端回复的全局请求，并在下次发送前等待应答；满 30 秒仍无应答计为一次无响应，连续 3 次将连接标为失效。对端完全不应答时，约 90 秒内进入失效。`keepalive_send` 返回成功只表示探测已写出，不得清零无响应计数。首期不向远程主机注入 Shell 集成脚本，不根据缺失的命令标记推断远程“空闲”。关闭远程终端始终提示可能有运行任务。断开 SSH 只能结束连接，不能承诺清理远程 nohup、tmux 或服务进程。应用退出不因仅存在远程终端而额外确认。

#### 5. SFTP 浏览与路径边界

SFTP 连接独立于终端，传输不会占用终端的 Session 锁。每个远程工作区一次最多执行一个文件传输，目录浏览请求在文件数据块之间调度，避免整次大文件传输阻塞目录操作；排队任务上限 100，满时拒绝新增并提示。

远程路径由 POSIX 字符串模型处理：`/` 分隔、区分大小写、拒绝 NUL，不经过 Windows `canonicalize` 或本地 `validate_relative_path`。初始目录由 SFTP `realpath(".")` 获取；用户可浏览服务端账号有权访问的目录，不把初始目录当作沙箱。

目录返回名称、类型、字节大小和 mtime。类型来自 `lstat`，不用会跟随符号链接的 `stat`。大目录按有界批次返回，前端支持增量显示与取消。通过服务端 realpath 规范化手动输入的路径。非 UTF-8 文件名显示明确的不支持状态，不使用有损转换发起传输。

下载目标使用专门的本地目录授权与路径校验。Rust 命令打开系统目录对话框，把所选目录签发为后端持有的目标令牌；前端对话框 API 返回的路径字符串不能作为授权，也不能靠任意本地路径绕过选择。逐级拒绝 `..`、绝对子路径、Windows 保留名、非法字符、大小写折叠冲突以及可导致逃逸的重解析点；错误明确列出，不静默改名覆盖。

符号链接显示其类型；递归传输不跟随链接，跳过并在结果中列出。FIFO、socket、设备文件也跳过。首期传输普通文件和目录，不保留属主、ACL、扩展属性或 Unix 执行位；上传权限由服务端创建行为决定，界面说明此限制。

#### 6. 传输任务、覆盖与取消

任务状态：`queued → scanning → running → completed`，分支包括 `awaitingConflict`、`cancelling → cancelled` 和 `failed`。目录任务支持部分完成，结果必须区分成功、失败、跳过和取消文件。

- Rust 负责目录遍历及分块 I/O，文件正文不经过 WebView。每块以 64 KiB 为起始实现参数；每块检查取消，聚合进度最多每 200 毫秒通知一次。
- 同名目标由用户选择覆盖、跳过或取消，支持本次任务统一处理。覆盖许可绑定目标元数据快照；提交前变化时重新提示。对外部并发修改的竞态明确报错，不能宣称整个目录原子替换。
- 上传先以排他创建方式写入目标同目录的 `.orbyte-transfer-<UUID>.part`，关闭成功后再提交。下载先在目标目录内写入临时文件。未完成时不提前截断现有目标文件。
- 远程提交和本地下载提交分开处理。远程目标不存在时使用禁止覆盖的提交方式；目标已存在时，只有服务器能够安全替换才提交，否则保留原文件并使该项失败。不采用先删除原文件再重命名。SFTP rename 的标记只表达原子／覆盖偏好，不能据此承诺所有服务器都原子替换，见 [SFTP rename 文档](https://docs.rs/ssh2/latest/ssh2/struct.Sftp.html#method.rename)。
- 本地下载的临时文件与最终目标在同一目录。提交时使用 Windows 替换式重命名覆盖已有文件，使该文件名始终指向一个完整文件。替换失败时保留原文件，并报告临时文件路径。
- 失败／取消时尽力清理本任务临时文件；断网清理失败则显示精确残留路径。文件面板不能删除这些残留，由用户在终端中处理。清理不得删除其他会话的临时文件。取消目录任务不回滚此前已成功提交的文件，也不删除之前创建的目录。
- 传输前后检查源文件大小和修改时间；发生变化时标记失败。集成验收用 SHA-256 核对内容，产品不把“大小相同”宣传为完整性校验。
- 首期不提供暂停、续传和自动重试；“重新传输”创建新任务，只选择失败项时也需再次检测目标冲突。
- SFTP 无进度超时 30 秒判失败；本地 I/O 返回后检查取消。网络正常或断开测试中取消应在 3 秒内进入最终状态；平台磁盘 I/O 阻塞时不能承诺硬中断，退出按全局预算结束应用。

#### 7. 命令、权限与应用生命周期

新增命令按领域划分，以下名称为拟新增接口：

| 领域 | 接口与约束 |
| --- | --- |
| 配置 | `list/create/update/delete_ssh_connection`、`forget_ssh_host_key`；只返回非敏感字段。 |
| 工作区 | `load/save_remote_workspace`、`create/remove_remote_terminal_config`；验证连接、工作区及终端归属。 |
| 连接 | `connect_ssh_terminal`、`connect_sftp`、`answer_ssh_challenge`、`cancel_ssh_attempt`；返回 attemptId，挑战通过专用 Channel 发送。 |
| 终端 | 复用 write／resize／stop／subscribe／ack 的公开语义，后端按 terminalId 查询本地／远程注册表；不信任前端传入的 kind。远程标识不参与本地失联轮询。 |
| 文件 | `list_remote_directory`、`create_remote_directory`、`select_transfer_paths`；远程路径与本地授权令牌分开。选择目录的对话框在 Rust 侧打开。 |
| 传输 | `enqueue/list/cancel_remote_transfer`、`resolve_transfer_conflict`、`subscribe_remote_transfers`；查询快照与事件 revision 配合，WebView 重载不丢运行状态。 |

同步修改 Tauri `build.rs` 命令清单、`lib.rs` 注册及 `capabilities/default.json` 权限；生成权限文件遵循仓库现有生成方式。后台拒绝已删除配置、过期挑战、跨工作区资源与退出期间的新任务。

应用退出只在两类情况下进入确认：存在未保存本地编辑，或存在排队／运行中的传输。仅有远程终端、没有这两类事项时，与当前本地终端一样直接退出。确认框按实际事项显示：

- 只有未保存文件：沿用保存、放弃、取消。
- 只有传输：说明退出会取消传输，只提供继续退出和取消，不出现保存或放弃。
- 两者都有：同一对话框里同时给出文件选择和传输说明。

`ClosePhase` 在同一临界区内读取传输计数，并同时拒绝新的传输、挑战和连接。用户取消退出后恢复接受新任务，不停止已有传输。确认退出后取消挑战及传输、关闭 SSH／SFTP socket，再清理本地终端。正在握手的尝试靠关闭 socket 立即结束，不等待 10 秒连接超时。全局清理预算仍为 3 秒，多个会话的超时不得相加。Windows Job 不能代替 SSH socket 和 worker 清理。

诊断继续只记录受控事件、随机 ID、错误分类、耗时和字节计数，不记录密码、口令、私钥、命令、输出正文和完整远程路径。密码和口令参数不进入诊断上下文。传输快照等高频命令加入 `diagnostics.ts` 的静默名单。所有新增界面文案进入 `zh.ts`／`en.ts`。

#### 步骤 1：Windows 协议与依赖验证

- 依赖：无。
- 目标：用可重复执行的探针验证选型，不先铺开 UI。
- 模块：新 `orbyte-ssh`、workspace 依赖、测试夹具及脚本。
- 改动：建立隔离 Linux OpenSSH 测试服务器启动说明。夹具开启 `PasswordAuthentication`，并另备一份只提供 keyboard-interactive 的对照配置。验证 Windows MSVC 构建、密码、Ed25519／RSA 加密与未加密私钥、按算法保存的主机指纹、PTY resize、SFTP `lstat`、路径和 rename 行为，以及非阻塞取消。记录实际原生库依赖和许可证，锁定通过的版本。探针以 `#[ignore]`、独立 feature 或环境变量与普通测试隔离。
- 验证：在 Windows 显式执行真实协议探针。无 PuTTY、无系统 ssh 客户端依赖仍可运行。协商出现 SHA-1 主机密钥、密钥交换或 MAC 即失败。对端不应答保活时约 90 秒内进入失效，探测发送成功本身不算通过。只提供 keyboard-interactive 的服务器返回明确错误且不发送密码。不支持安全覆盖时返回失败。普通 `cargo test` 在没有服务器时仍可运行。任一必需能力不通过即不进入步骤 2，修正依赖或实现并重新验证，不能以降级主机校验换取通过。

实测结论（2026-10-31）：Windows 下 libssh2 默认使用 WinCNG 后端，只支持 RSA 主机密钥，无法满足 Ed25519 与 curve25519 要求；`orbyte-ssh` 已改为同时启用 `openssl-on-win32` 与 `vendored-openssl`。隔离 OpenSSH 夹具的 8 项探针全部通过：密码认证、Ed25519／RSA／加密 Ed25519 私钥、按算法主机密钥、keyboard-interactive 拒绝、弱算法拒绝、PTY resize、SFTP 与双向传输。保活 90 秒、1 GiB 往返、安装版内存与回显仍待步骤 8 记录。

| 公共终端代码变更影响成熟的本地功能 | 只抽取两种会话实际需要的接口；保留 PTY 生命周期及 Job；先跑本地回归再接 UI。 |
| 独立连接需要更多认证及服务器连接额度 | 用隔离避免 SFTP 阻塞终端。一次连接动作共用同一次密码输入；之后单独新建的终端再认证。先采用串行传输，不引入连接池。 |
| 不保存密码带来重复输入 | 首期优先可审查的凭据边界。同一次输入不落盘，认证结束即从内存清除。不把系统凭据管理扩展到本轮范围。 |
| libssh2 默认算法和保活语义偏宽 | 显式收紧算法偏好。保活使用要求回复的探测和读超时计数。步骤 1 用弱算法协商和不应答对端验证失败路径。 |
| 同一端点有多把主机密钥 | 按算法保存，已保存算法优先协商。同算法公钥变化时拒绝认证。不允许降级到未信任密钥。 |
| 本地会话轮询误判远程终端 | 远程会话不参加 `list_terminal_sessions` 的失联判定，远程输出不解析 Shell 集成序列。 |
| 远程文件系统差异 | 协议测试分别验证远程提交和本地下载覆盖。远程无法安全提交则失败并保留原文件。本地下载用替换式重命名。不承诺所有服务器原子覆盖。 |
| 递归目录可能很大或传输中变化 | 流式扫描、有界队列、取消、用 `lstat` 跳过链接、检测源变化；目录结果允许部分成功。 |
| 首次信任仍依赖用户核对指纹 | 提供完整端点、算法及 SHA-256 指纹。DNS 大小写和等价 IPv6 写法归一。服务端同算法密钥改变时中止，并按算法管理旧信任。 |
| 退出确认与进行中的连接竞态 | 传输计数和拒绝新任务在同一临界区。握手取消靠关闭 socket，避免 10 秒超时吃掉 3 秒退出预算。SSH 循环使用专用线程。 |
| SSH 断线不等于远程任务停止 | 保留断线状态与屏幕。关闭单个远程终端始终说明进程可能仍在运行。应用退出不因仅有远程终端而额外确认，也不宣称清理所有远程进程。 |

跳板机、端口转发和远程编辑按 C02 不进入本期；agent、凭据库、MFA、ssh_config 导入、断点续传、远程同步和权限管理也不作为本期交付承诺。

### 验收标准

1. 在未安装 PuTTY／OpenSSH 客户端的 Windows 安装环境中，新建连接后能通过密码及约定的私钥格式登录 Linux。自定义端口、DNS、IPv4、IPv6 均有测试结果。只提供 keyboard-interactive 的服务器给出明确失败，并且没有发送口令。协商出现 SHA-1 主机密钥、密钥交换或 MAC 时连接失败。
2. 某个端点的某个算法第一次出现时必须先确认主机指纹。保存后再次连接，同算法公钥匹配才能认证。同算法密钥被替换时阻止认证。已信任算法不能降级到未信任密钥。DNS 名大小写和等价 IPv6 写法命中同一信任记录。取消或过期确认不会启动会话。
3. 同时连接两台服务器，每台至少两个终端。同一工作区一次连接动作只索取一次密码。输入、中文、Ctrl+C、Tab、窗口 resize、`vim`／`top` 全屏交互和终端输出互不串线。切换本地项目不关闭远程终端。远程会话不会因本地会话名单缺失而被标成已退出，远程输出也不触发本地 Git 刷新。
4. 连接信息和远程布局重启保留，但不自动连接。SQLite、日志和诊断上下文中不存在密码、私钥口令或私钥正文。关闭「关闭页签和窗格前确认」后，关闭远程终端仍会提示远端任务可能仍在运行。
5. 可浏览、刷新和创建有权限的目录。符号链接以 `lstat` 类型显示，浏览和递归传输都不跟随。无权限或 SFTP 不可用时明确提示，SSH 终端仍可独立使用。本地下载目录由 Rust 签发令牌，前端任意路径字符串不能授权。
6. 双向传输空文件、中文／空格文件名、空目录、多层目录及单个 1 GiB 文件，文件内容 SHA-256 一致。大小写冲突、非法 Windows 名称和符号链接按设计报告。
7. 同名文件覆盖需明确选择。远程无法安全替换时保留原文件并使该项失败。本地下载覆盖使用替换式重命名，失败时原文件仍在。取消、磁盘满、权限拒绝和中途断网不截断原目标。任务结果准确报告已完成项和残留临时路径，文件面板不能删除这些残留。
8. 传输 1 GiB 文件时，worker 内存相对稳定连接基线的额外占用不超过 64 MiB（不含用户配置的终端回滚）。正常网络及断网场景取消在 3 秒内结束。局域网持续传输期间终端输入回显 p95 不高于 200 毫秒，记录服务器与网络条件。对端不应答保活时约 90 秒内把连接标为失效。
9. WebView 重载后从快照恢复正在运行的任务，不重复创建。只有未保存文件、只有传输、两者都有这三种退出确认与对应按钮一致。取消退出后任务继续且可以再次入队。确认退出在全局 3 秒预算内关闭资源，正在握手的连接不等待 10 秒超时。仅有远程终端时直接退出。远程后台进程不作终止承诺。
10. 本地项目、文件编辑、草稿恢复、Git、终端输入／输出恢复和退出流程回归通过。普通 `cargo test` 不依赖真实服务器。协议探针由发布检查显式执行。新增自动化测试、协议集成验收、依赖审计、第三方声明及安装版验证均有可追溯结果。
